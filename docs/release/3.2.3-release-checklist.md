# Lets-Plot Compose 3.2.3 Release Checklist

This checklist starts after the 3.2.3 release-candidate readiness gate is green.

## Current pre-release state

The development line is intentionally not publishable yet while any of these
versions still end in `-SNAPSHOT`:

- `letsPlotCompose.version=3.2.3-SNAPSHOT`
- `letsPlot.version=4.11.1-SNAPSHOT`
- `letsPlotKotlin.version=4.15.1-SNAPSHOT`

The `release-dependency-preflight` CI job records this as
`BLOCKED_EXPECTED_PRE_RELEASE`. This is a successful pre-release state, not a
release failure.

## Upstream dependency gate

Before finalizing Lets-Plot Compose 3.2.3:

1. Lets-Plot core 4.11.1 must be available as a released artifact.
2. Lets-Plot Kotlin API 4.15.1 must be available as a released artifact.
3. Update `letsPlot.version` and `letsPlotKotlin.version` to the released
   versions.
4. Re-run the complete compatibility workflow.

When both upstream dependencies are non-SNAPSHOT while the project remains
`3.2.3-SNAPSHOT`, preflight changes to
`READY_FOR_VERSION_FINALIZATION`.

For non-SNAPSHOT dependency versions, the preflight also downloads the corresponding Maven Central POMs for `lets-plot-common` and `lets-plot-kotlin`. A version string alone is therefore not sufficient: the artifacts must actually be available from the release repository.

## Final version preparation

After the upstream dependency gate is clear:

1. Set `letsPlotCompose.version=3.2.3` in `gradle.properties`.
2. Convert the CHANGELOG `[Unreleased]` section into the 3.2.3 release entry
   with the release date.
3. Update README dependency examples only when the corresponding public
   artifacts are available.
4. Run the full compatibility workflow again.
5. Require the release dependency preflight state to be
   `READY_FOR_RELEASE_BUILD`.

CI rejects a final `3.2.3` project version if either Lets-Plot dependency is
still a SNAPSHOT.

## Release build and publication

The existing Gradle publication path is:

- release Maven staging directory: `build/maven/artifacts`
- bundle task: `packageMavenArtifacts`
- Central upload task: `uploadMavenArtifacts`
- signing: enabled automatically for non-SNAPSHOT project versions

The preflight job never invokes the upload task and never sends credentials or
artifacts to an external repository.

For the actual release:

1. Build and sign all release publications.
2. Inspect the generated Maven bundle before upload.
3. Confirm root Gradle module metadata references Desktop, Android, and WasmJS
   target publications.
4. Confirm sources and javadoc artifacts are present where required.
5. Run `packageMavenArtifacts`.
6. Upload with `uploadMavenArtifacts` only after the signed bundle has been
   reviewed.
7. Complete the user-managed Central publication flow.
8. Tag the exact release commit and create the GitHub release.
9. Verify the released artifacts from a clean external consumer.

## Renderer boundary

3.2.3 production Desktop rendering remains Native Canvas. Graphite readiness
continues as a separate experimental CI track and must not be treated as part of
the production release switch.
