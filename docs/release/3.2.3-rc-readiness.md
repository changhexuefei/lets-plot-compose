# Lets-Plot Compose 3.2.3 RC Readiness

This document defines the release-candidate evidence contract for the current
`3.2.3-SNAPSHOT` development line.

## Production baseline

| Item | Baseline |
| --- | --- |
| Kotlin | 2.4.20 |
| Compose Multiplatform | 1.12.1 |
| Lets-Plot Kotlin API | 4.15.1-SNAPSHOT |
| Lets-Plot core | 4.11.1-SNAPSHOT |
| Production Desktop renderer | Native Canvas |
| Android compile SDK | 35 |
| Android minimum SDK | 24 |

## Published-consumer evidence

The release-candidate gate validates the library from the same boundary used by
an external application. The standalone consumers do not depend on repository
projects.

| Target | Release-facing check |
| --- | --- |
| Desktop | Windows/JDK 21 standalone consumer resolves the CI Maven bundle, runs the interaction/render smoke, and emits 9 screenshots |
| Android | Standalone Kotlin Multiplatform consumer resolves the published Android variant and assembles a release AAR |
| WasmJS | The same standalone consumer resolves the published Wasm variant and builds the production webpack JS/Wasm bundle |

The frontend Maven bundle must contain all four publication coordinates for
`3.2.3-SNAPSHOT`:

- `lets-plot-compose`
- `lets-plot-compose-desktop`
- `lets-plot-compose-android`
- `lets-plot-compose-wasm-js`

The root Gradle module metadata must also reference all three platform target
publications. This protects against a common failure mode where in-repository
target compilation passes but an external consumer cannot resolve a published
variant.

## CI contract

The `release-candidate-readiness` job depends on the normal Compose
compatibility build, the Core publication bundle, the Windows standalone
consumer, and the Android/Wasm standalone consumer.

A successful gate uploads `3.2.3-rc-readiness.txt` with:

- `result=RELEASE_CANDIDATE_READINESS_PASS`
- `consumer.boundary=PUBLISHED_MAVEN_ONLY`
- Desktop, Android, and Wasm consumer checks marked `PASS`
- root/Desktop/Android/Wasm publication inventory marked `PASS`
- `production.renderer.default=NATIVE_CANVAS`
- `graphite.production=DISABLED`

## Graphite boundary

Graphite remains an experimental, explicit opt-in readiness track. Its
Windows/JDK 21 + Compose 1.13.0-alpha01 + Skiko 0.153.0 evidence is maintained
by the separate Graphite readiness gate.

Graphite probe success is not a production renderer switch and is not required
to describe the 3.2.3 production renderer. The production default remains
Native Canvas until a separate adoption decision changes that contract.

## Change policy

After this baseline is green on `main`, changes on the 3.2.3 stabilization
line should be limited to release preparation or fixes for concrete regressions.
New renderer adoption or broad feature work should remain separate from the
3.2.3 release-candidate baseline.
