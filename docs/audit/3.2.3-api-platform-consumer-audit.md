# Lets-Plot Compose 3.2.3 API / Platform / Consumer Audit

This audit focuses on the production Native Canvas path. The experimental Graphite
track is intentionally out of scope except for confirming that no production
renderer boundary changes are introduced.

## Public API

| Area | Finding | 3.2.3 action |
| --- | --- | --- |
| `PlotPanel` defaults | Consumers had to pass a `Modifier` and computation-message callback even when no customization was needed. | Add source-compatible defaults. |
| `PlotPanelRaw` defaults | Raw-spec consumers also had to pass aspect-ratio, modifier, and callback boilerplate. | Add source-compatible defaults. |
| KDoc | `PlotPanel` and `PlotPanelRaw` documented a removed `legacyRendering` parameter. | Remove stale documentation. |
| FigureModel lifecycle | External `PlotFigureModel` ownership is already documented; internally created models are disposed by `PlotPanelRaw`. | Keep contract. |
| Utility surface | `containsBackground`, `sandbox/SandboxToolbarCmp`, and `util/NaiveLogger` are public-looking implementation helpers. | Do not make a breaking visibility change during 3.2.3 stabilization; review for a later API cleanup. |
| Export API | Android exposes `ggsave(Uri, Context, ...)`; Desktop export is provided through the AWT stack and Wasm has no equivalent facade. | Record as a future cross-platform export API design item, not a 3.2.3 blocker. |

## Real consumer boundary

The repository validates published Maven artifacts rather than relying only on
in-repository compilation:

- Desktop: Windows/JDK 21 runtime smoke with render, resize, tooltip, wheel zoom,
  drag pan, density changes, close, and reopen evidence.
- Android: standalone KMP consumer resolves the published Android variant and
  assembles a release AAR.
- WasmJS: the same standalone KMP consumer resolves the published Wasm variant
  and produces a production webpack JS/Wasm bundle.
- Public API defaults are compiled from both the Desktop standalone consumer and
  the Android/Wasm common consumer.

### Remaining consumer gap

Android and Wasm consumer validation currently proves publication resolution and
compilation/package shape, but not end-to-end runtime pointer interaction in an
emulator/browser. A browser-driven Wasm interaction smoke is the next practical
runtime parity step; Android emulator interaction smoke should follow only if it
can remain deterministic and reasonably lightweight.

## Renderer boundary

This audit does not change the production Desktop renderer:

- production default: **Native Canvas**
- Graphite: experimental / explicit opt-in evidence only
- production Graphite dependency: absent
